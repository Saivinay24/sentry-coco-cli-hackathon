Anomalies don't wait for a human to notice them.

Sentry watches operations data living in Snowflake and investigates return-rate spikes the moment they land, no dashboard to refresh, no query to run by hand. How it thinks

The full reasoning chain, not just an answer

Every step is logged, so the confidence score and recommendation are traceable back to the actual evidence, not asserted.
01
Test, don't eyeball
A one-sample proportion z-test compares the SKU/warehouse's current 7-day return rate against the fleet-wide baseline rate, not a fixed threshold, and not a thin per-combo history that would give a false read.
02
Pull the actual evidence
The top return reasons behind the spike are pulled directly from the return records, so the model reasons over real text, not a summary of a summary.
03
Reason with Cortex COMPLETE
The statistics and evidence are handed to SNOWFLAKE.CORTEX.COMPLETE (llama3.1-70b), which returns a root-cause hypothesis, a confidence score, and a concrete recommended action, in Snowflake, next to the data.
04
Log the whole trace
The numbers, the evidence, and the model's reasoning all land in SENTRY_TRACE, an audit trail, not a black box a human has to trust blind.
05
Trigger the action
The same run opens a ticket in SENTRY_ACTIONS: priority set from the z-score, owning team assigned by Cortex from the evidence. The pipeline ends in something a team can act on, not a line in a log nobody reads.
Why this holds up

Built and verified live against Snowflake, not staged

Real autonomy, not a button
The trigger is a genuine Snowflake Stream + scheduled Task. Most one-day builds fake this with a manual "run" button. This one doesn't have one.
Built live with CoCo CLI
Schema, seed data, the stored procedure, and the Stream/Task were built and debugged against a real Snowflake trial account using cortex exec: real errors, real iteration.
Honest statistics
The anomaly threshold is a real z-test against a fleet-wide baseline, verified against seeded data before any reasoning logic was layered on top.
A real UI, not just SQL
A Streamlit-in-Snowflake dashboard reads SENTRY_TRACE live. This page is a snapshot of that same table for anyone without Snowflake access.
Triggers an action, not just an opinion
Every confirmed anomaly opens a prioritized, team-routed ticket in SENTRY_ACTIONS: priority computed from the z-score, team assigned by Cortex from the evidence. The pipeline ends in a triggered action, not a paragraph.

Built in roughly one day for the Snowflake CoCo CLI Hackathon 2026. Single data domain (returns and orders), no multi-user auth, no production-hardened error handling beyond the happy path, said plainly rather than implied otherwise. The native Streamlit-in-Snowflake app requires Snowflake account access to view, which is normal for a Snowflake-native app; this page exists so anyone can see the real result without that requirement.
