ANOMALY_SCAN_TASK checking

Sentry runs inside Snowflake as a scheduled Task watching a Stream on the returns table. Nobody starts it. When new returns land it wakes up, tests them against the fleet baseline, and if the spike is real it investigates and opens a ticket. When there is nothing new it goes straight back to sleep without burning compute.

What it does on each wake-up SENTRY_DB.OPS.ANOMALY_SCAN()
01
Check what changed
Reads the Stream to see which returns are new since the last run, then drains it so the same rows are never investigated twice.
02
Test, don't eyeball
Runs a one-sample proportion z-test on each SKU and warehouse against the fleet-wide baseline rate. No fixed threshold, and combinations with too few orders are skipped rather than guessed at.
03
Gather the evidence
Pulls the actual reasons customers gave for those returns, so the reasoning is grounded in the real text rather than a summary of a summary.
04
Work out the likely cause
Hands the statistics and the evidence to Cortex COMPLETE, which returns a root-cause hypothesis, a confidence score, a recommended action, and which team owns it.
05
Open a ticket and log the trace
Writes the full reasoning to SENTRY_TRACE and opens a ticket in SENTRY_ACTIONS, with priority computed from the z-score rather than chosen by the model.
Every time it woke up straight from Snowflake task history
